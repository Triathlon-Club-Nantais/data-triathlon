# Navigation, couche 1 : back-office séparé (#1296) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Le rail et le tiroir ne montrent que l'espace courant (public ou back-office) ; un sélecteur d'espace et une entrée « Back-office · N » mènent au sommaire `/admin`.

**Architecture:** `nav.config.ts` gagne un champ `space` par section et deux helpers (`spaceOf`, `SPACES`). `AppNav` filtre ses sections sur l'espace déduit de l'URL ; la barre basse reste calculée sur l'espace public (elle change par espace en couche 3) ; la palette ⌘K garde tous les espaces accessibles. Un composant `SpaceSwitcher` (menu `@base-ui/react`) s'insère dans l'en-tête du rail et dans la barre mobile du haut.

**Tech Stack:** Next.js 16, React, TypeScript strict, Vitest + Testing Library, `@base-ui/react` 1.8 (`Menu.LinkItem`), `components/ui/dropdown-menu.tsx`.

**Spec:** `docs/superpowers/specs/2026-10-10-navigation-espaces-design.md`

## Global Constraints

- Copie utilisateur en français, vouvoiement ; « épreuve », « athlète ».
- Identifiants nouveaux en anglais ; commentaires seulement pour une logique non évidente ; aucun tiret (—, –, -) comme ponctuation dans la copie ni les commentaires.
- `nav.config.ts` reste la description **unique** de la navigation ; rien de codé en dur dans `AppNav`.
- La navigation n'est jamais une garde : elle évite d'annoncer un écran qui rendrait 403, les routes gardent leurs gardes.
- Commits Conventional Commits, **sans** `Co-Authored-By`, avec `Refs #1296`.
- Git via `/usr/bin/git`. Depuis `frontend/` : `npm ci` si `node_modules` manque ; `npx vitest run <fichiers>`, `npm run lint`, `npx tsc --noEmit`.
- Prérequis : la branche de travail contient le correctif #1300 (`bottomBar` dans `NavItem`, « Plus » toujours rendu).

- Couche 1 : la section « Jeunes » appartient à l'espace `admin` (ses routes sont encore sous `/admin/jeunes`) ; la couche 2 la passera à `encadrement`.

```ts
export type SpaceId = "public" | "encadrement" | "admin";

/**
 * Les trois espaces de la navigation (#1295) : le rail et le tiroir ne
 * montrent que celui de la page courante. `home` est la destination du
 * sélecteur d'espace ; sans elle, la première destination visible en tient
 * lieu.
 */
export const SPACES: Record<SpaceId, { label: string; home?: string }> = {
  public: { label: "Résultats", home: "/dashboard" },
  encadrement: { label: "Encadrement" },
  admin: { label: "Back-office", home: "/admin" },
};

/** Par préfixe de segment : `/administration` n'est pas `/admin`. */
export function spaceOf(pathname: string): SpaceId {
  const segment = pathname.split("/")[1];
  return segment === "admin" || segment === "encadrement" ? segment : "public";
}
```

Ajouter `space: SpaceId;` au type `NavSection`, puis `space` à chaque section de `NAV` : `consulter` et `club` → `"public"` ; `admin`, `utilisateurs`, `jeunes` → `"admin"`.

### Task 2: `AppNav` ne montre que l'espace courant

**Files:**
- Modify: `frontend/components/layout/AppNav.tsx` (calcul de `sections`, `barreItems`, `sectionsReste`, `sectionsTiroir`, props de `AthletePicker`, l.131-190 et l.505-525)
- Test: `frontend/components/layout/AppNav.test.tsx`

**Interfaces:**
- Consumes: `NavSection.space`, `spaceOf`, `SPACES`, `TO_HANDLE` (Task 1 et existant).
- Produces, dans `AppNav` : `toutesSections: SectionRendue[]` (toutes les sections visibles, tous espaces), `espace: SpaceId` (de `spaceOf(pathname)`), `sections` (celles de `espace`), `espacesOuverts: { id: SpaceId; label: string; href: string; count?: number }[]`, consommé par la Task 3.

**Comportement :**
1. `toutesSections` = le calcul actuel de `sections` (filtre `minRole`, `estVisible`, badges, sections vides retirées).
2. `espace = spaceOf(pathname)` ; `sections = toutesSections.filter((s) => s.space === espace)`.
3. La barre basse prend ses onglets dans les sections **publiques** de `toutesSections` (inchangée quel que soit l'espace, jusqu'à la couche 3) ; « le reste » (`sectionsReste`) et le repli de #621 se calculent sur `sections` (l'espace courant) : en back-office, le tiroir porte les écrans du back-office.
4. `espacesOuverts` : un espace par `SpaceId` qui a au moins une section dans `toutesSections`, **plus** `admin` si `session?.can_administer` (le sommaire `/admin` existe même si aucune entrée n'est visible). `href` = `SPACES[id].home` sinon la première destination visible de l'espace. `count` de `admin` = somme des `count` des destinations visibles du groupe `TO_HANDLE` (indéfini si aucune n'a de compteur). Ordre : `public`, `encadrement`, `admin`.
5. Dans l'espace public, si `espacesOuverts` contient `admin`, le rail et le tiroir ajoutent **en dernier** une section synthétique `{ id: "vers-admin", label: "Back-office", icon: Briefcase, space: "public", minRole: ROLE.CONNECTED, root: true, items: [{ id: "backoffice", label: "Back-office", href: "/admin", icon: Briefcase, count }] }` (même `count` que le point 4), rendue par `NavContent` comme les autres.
6. La palette ⌘K (`AthletePicker screens`) prend `toutesSections` au lieu de `sections` : elle reste le raccourci transversal. Le reste de sa liste (`Back-office`, `Guide d'administration`) ne change pas.

**Interfaces:**
- Consumes: `espacesOuverts` et `espace` de la Task 2 ; `SPACES`.
- Produces: `export function SpaceSwitcher({ current, spaces }: { current: SpaceId; spaces: { id: SpaceId; label: string; href: string; count?: number }[] }): JSX.Element | null`

**Comportement :** rend `null` si `spaces.length < 2`. Sinon un déclencheur `DropdownMenuTrigger` (classe `tcn-btn tcn-btn--sm tcn-btn--secondary`) dont le texte est le libellé de l'espace courant suivi d'un chevron (`ChevronDown` de `lucide-react`, `aria-hidden`), nom accessible « Espace : <libellé>, changer d'espace ». Le menu liste chaque espace en lien (`Menu.LinkItem` de `@base-ui/react/menu`, rendu par `next/link` via sa prop `render`), l'espace courant marqué `aria-current="page"`, et son compteur s'il est défini et non nul, avec le même nom accessible que les pastilles du rail (`libelleCompteur` de `@/lib/queries/nav-badges`). Lire `components/ui/dropdown-menu.tsx` et `node_modules/@base-ui/react/menu/link-item` pour l'API exacte ; si l'enveloppe `ui/` n'expose pas de `LinkItem`, l'ajouter à `components/ui/dropdown-menu.tsx` sur le modèle de `DropdownMenuItem` (mêmes classes), exporté sous `DropdownMenuLinkItem`.

Placement : dans l'en-tête du rail **déplié**, à droite du logo ; rail replié : sous le monogramme, en icône seule (`LayoutGrid` de `lucide-react`) avec le même nom accessible et une infobulle (`Tooltip`, patron de l'existant) ; barre mobile du haut : entre le logo et le bouton de recherche.
