# Épreuve cible et objectif majeur (#1694) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** un objectif de saison peut viser une épreuve (importée ou saisie par nom et date), avec un temps visé facultatif, et un objectif par saison peut être « majeur » : il est mis en avant en tête de Mon espace avec un compte à rebours, rappelé dans la colonne de droite, et se clôt seul quand le résultat arrive.

**Architecture:** la table `season_goals` gagne `course_id`, `race_name`, `race_date`, `major` et `target` devient nullable (une migration Alembic). Le service `season_goals` valide la sorte `race`, tient le majeur unique et calcule à la lecture un champ ajouté `outcome`. Le front étend le formulaire de `SeasonGoals`, ajoute une mise en avant `ObjectifMajeur` (centre) et `RappelObjectifMajeur` (colonne de droite), et le récap de #1669 lit `outcome`.

**Tech Stack:** FastAPI, SQLAlchemy 2.0, Alembic, Pydantic v2, pytest ; Next.js 16, TanStack Query, vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-20-mon-espace-vague-2-design.md` (sections « #1694 » et « Précisions #1694 »).

**Base:** branche `feat/1694-target-race` partie de `feat/1669-recap-goals` (qui contient PR #1723) : `SeasonGoals.tsx` y a déjà son mode lecture seule et `RecapObjectifs` existe.

## Global Constraints

- Principe IV : champs **ajoutés** à `SeasonGoalRead` (`course_id`, `race_name`, `race_date`, `major`, `outcome`) ; `target` devient `int | None`, `null` seulement pour un objectif `race` sans temps visé ; `reached` reste.
- Migration : avant de l'écrire, `git fetch origin && git rebase origin/main`, puis `uv run alembic heads` doit afficher **une seule** tête. Jamais d'`alembic upgrade` contre une base réelle (`backend/.env` peut viser la prod) : les tests créent leur schéma.
- Un résultat « validé » au sens de l'objectif : mêmes exclusions qu'`athlete_season_times` (en attente, DNF, DNS, DSQ, relais, épreuve non fiable).
- Privé : tout passe par `/auth/me/goals`, rien sur la fiche publique.
- Texte visible en français, vouvoiement ; identifiants, tests, commits en anglais. Jamais de tiret (—, –, -) comme ponctuation dans les commentaires, textes UI, messages de commit ou corps de PR (« J‑12 » est une notation, pas une ponctuation).
- Un squelette ou un état vide teste `isPending`, jamais `isLoading` (`frontend/AGENTS.md`).
- Ne pas toucher : config pytest/vitest, conftest, ci.yml, `frontend/app/login`, `/account`, `components/auth`, la fiche athlète, les écrans jeunes.
- Aucun trailer `Co-Authored-By`, aucune mention d'IA.

## Review Focus

- Épreuve cible le jour même : `outcome` vaut `upcoming` toute la journée de `race_date` (comparaison de dates, pas d'heures), le compte à rebours dit « aujourd'hui ».
- Épreuve importée supprimée ou absorbée par une fusion : l'objectif ne casse pas, il retombe sur la saisie libre (nom et date recopiés à la création, `ON DELETE SET NULL`).
- Résultat présent sans temps lisible alors qu'un temps est visé : `awaiting_results`, jamais `missed`.
- Passer un objectif majeur alors qu'un autre l'est : un seul majeur après l'appel, sans 409.
- Un objectif `race` dont la date tombe hors de la saison en cours : 422 avec un message lisible.
